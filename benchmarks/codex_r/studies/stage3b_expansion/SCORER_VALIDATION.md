## 1. Validation Gate Architecture and Security Controls

Every Stage 3B task verifier (`verifier/<ID>.R`) was validated offline inside the pinned scorer containers via `python -m benchmarks.codex_r.studies.stage3b_expansion.selftest`.

### Container Hardening (`suite.docker_command`)
- **Network Isolation**: `--network none` (zero outbound or loopback network access beyond the isolated container).
- **Filesystem Isolation**: `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--user 65534:65534`.
- **Candidate Execution Isolation**: Candidate `solution.R` is loaded and invoked inside a separate `callr::r()` subprocess (`verifier/lib.R`), preventing candidate code from inspecting or mutating the verifier's environment, check counters, or oracle objects.
- **Result Forgery Prevention**: `suite.score()` requires exactly one `BENCH_RESULT=` line on stdout; if a candidate prints a forged `BENCH_RESULT=` line, `len(records) != 1` triggers `candidate_error` (`ambiguous_result`), and `callr` captures candidate stdout inside the subprocess.

## 3. Adversarial Audit and Hardening Highlights

1. **`XM01` (`DESeq2` Independent Filtering Threshold Discrimination)**:
   - Initial synthetic counts had zero low-mean genes, causing `DESeq2:::pvalueAdjustment` to select `filterTheta = 0` across all `alpha` levels (`0.01`, `0.05`, `0.10`), which allowed `wrong_alpha_only_in_the_final_filter` to pass.
   - Hardened `xm01_data` in `verifier/XM01.R` with 15 strongly differentially expressed genes and 60 low-count null genes (`base = 0.8`), producing distinct empirical `filterTheta` quantiles at `alpha = 0.01` (`0.4459`), `0.05` (`0.2133`), and `0.10` (`0.0000`). The `wrong_alpha_only_in_the_final_filter` control is now deterministically rejected (`5/10` checks).
2. **`XR05` (`purrr` Candidate-Session Invocation Counting)**:
   - Hardened `f_is_called_once_per_combination` in `verifier/XR05.R` so the counter closure executes inside the isolated `callr` candidate session via `call_candidate(probe)` and asserts `got$n_calls == 6L`.
3. **`XM03` (`shiny::testServer` Session & Cache Probing)**:
   - Encapsulated `shiny::testServer` probes inside `xm03_probe_module()` running inside `call_candidate()` with `environment(fn) <- globalenv()`, verifying reactive invalidation, cache-key isolation across cohorts/modes, and clean cache hits (`computes == 1L` on repeated cohort selection).
